# クリストファー 公式サイト 設計

## 方針

- 本文を HTML で配信し、検索とリンクカードに強い構成にする
- 公開する情報は 1 ページに縦に並べ、ヘッダーのリンクで各セクションへスクロールする
- DB は持たない。データの正本は Google カレンダーとリポジトリ内のファイルに置く
- 運用コストは 0 円。当面は `*.workers.dev` で公開し、独自ドメインは運用が定着してから判断する
- ライブ情報の更新は Google カレンダーへの登録だけで完結させる

## 技術スタック

| 用途 | 採用 | 理由 |
| --- | --- | --- |
| フレームワーク | Astro + TypeScript | 読むページが中心のサイトに向き、JavaScript をほぼ配信しない |
| スタイル | Tailwind CSS | 追加の実行コストがない |
| ホスティング | Cloudflare Workers（無料枠） | 静的ファイル配信とサーバー描画を 1 か所で扱える |
| ソース管理 / CI | GitHub | push で自動デプロイ |

操作の多い部品が必要になったら、その部分だけ React などのアイランドとして追加する。

## 構成

```
ブラウザ ──> Cloudflare Workers
              ├ 静的ファイル  404, 画像
              └ サーバー描画  / ──(API キー)──> Google カレンダー
                  └ 予定データを 10 分キャッシュ
GitHub ──(push で自動デプロイ)──> Cloudflare Workers
```

`output: "static"` と `@astrojs/cloudflare` を使い、`/` と告知画像のページだけ
`export const prerender = false` でサーバー描画にする。API キーはサーバー側だけで使い、
ブラウザには渡さない。定期ビルド方式は、反映が遅くビルド回数も増えるため採用しない。

## ページ

| パス | 内容 | データ元 | 描画 |
| --- | --- | --- | --- |
| `/` | 今後と過去のライブ、プロフィール、各種リンク | カレンダー + ファイル | サーバー |
| `/schedule/poster` | 月別の告知画像の作成（検索対象外） | カレンダー | サーバー |
| `/404` | 404 画面（HTTP 404 を返す） | なし | 静的 |

各種リンク（コンビの YouTube、2 人の X と Instagram、高橋の大喜利 YouTube）はトップの LINKS に置き、`src/data/links.ts` で管理する。

## ライブ情報の取得

`src/lib/calendar.ts` に実装し、ページから直接呼ぶ。公開 API は作らない。

```ts
type LiveEvent = {
  id: string;
  title: string;
  allDay: boolean;
  start: string; // 終日: YYYY-MM-DD、それ以外: ISO 8601
  end: string; // 終日: YYYY-MM-DD、それ以外: ISO 8601
  venue: string | null;
  doorsAt: string | null; // 開場時刻 HH:mm
  openAt: string | null; // 開演時刻 HH:mm（説明欄から読む）
  closesAt: string | null; // 終演時刻 HH:mm（説明欄から読む）
  price: string | null;
  ticketUrl: string | null; // http または https のみ
  description: string | null; // 上記以外の説明欄のプレーンテキスト
};

type ScheduleResult =
  | { status: "ok"; events: LiveEvent[]; fetchedAt: string; stale: boolean }
  | { status: "error" };

function getSchedule(range: "upcoming" | "past" | { month: string }): Promise<ScheduleResult>; // month: YYYY-MM
```

| `range` | 取得範囲 | 並び順 |
| --- | --- | --- |
| `upcoming` | 現在以降 | 日時の昇順 |
| `past` | 直近 1 年 | 日時の降順 |
| `{ month }` | 指定した月（`Asia/Tokyo` 基準） | 日時の昇順 |

- 取得は `events.list` を `singleEvents=true`、`orderBy=startTime` で呼ぶ
- `visibility` が `private` または `confidential` の予定と、タイトルのない予定は除外する（登録ミスへの備え）
- 日時は `Asia/Tokyo` で表示する
- Google の終日予定の `end` は翌日になるため、表示時は 1 日引く

### キャッシュ

Cloudflare Workers KV に `range` ごとの予定データを保存する。ページの HTML は保存しない。
Cache API は `workers.dev` では動作しない可能性が高く、当面の公開先で使えないため採用しない。

1. 取得から 10 分以内のキャッシュがあれば使う
2. なければ Google API から取得し、キャッシュを更新する
3. 取得に失敗し、古いキャッシュがあれば `stale: true` で使う
4. キャッシュもなければ `status: "error"` を返す

保存期間は 7 日とし、新しさは `fetchedAt` で判定する。

フッターの「ライブ情報を更新」ボタンで、カレンダーの変更をすぐ反映できる。

- `DELETE /api/schedule-cache` で押した時刻を KV に保存し、それより前に取得したキャッシュを使わない
- 誰でも押せるため、Google API と KV の無料枠を守るよう、サイト全体で 5 分に 1 回までとする
- KV は反映に最大 60 秒ほどかかるため、別の地域からのアクセスでは少し遅れることがある
KV の読み書きに失敗しても、取得できた予定は表示する。

`month` は `YYYY-MM` の形式を検証し、当月の前後 12 か月に制限する。
Google API の呼び出しを任意の月の指定で増やされないようにするため。

### 画面の表示

| 状態 | 表示 |
| --- | --- |
| `stale: true` | 通常の一覧に「最新でない可能性があります」と添える |
| `status: "error"` | 取得失敗の案内と X へのリンク |
| 0 件 | 「現在予定はありません」 |

## データ

### ライブ情報（Google カレンダー）

2 人で更新する共用カレンダーを新規作成して公開し、サイトはこのカレンダーだけを読む。
カレンダーにある予定はすべて公開情報として扱い、解禁済みのライブだけを入れる。

| カレンダー | 公開範囲 | 入れるもの |
| --- | --- | --- |
| 高橋、齊藤の個人カレンダー | 非公開 | 私用の予定、未発表のライブ、ネタ合わせなど |
| 共用カレンダー | 公開 | 解禁済みのライブ |

高橋が作成し、齊藤に「変更および共有の管理権限」を渡す。どちらかが使えなくなっても
管理を続けられるようにするため。

| カレンダーの項目 | サイトでの表示 |
| --- | --- |
| タイトル | ライブ名 |
| 開始 | 入り時間（サイトには表示しない。日付と並び順に使う） |
| 終了 | 終了時刻（今後と過去の振り分けに使う） |
| 場所 | 会場（空なら説明欄の `会場:` の行） |
| 説明 | 開場、開演、終演、料金、チケット URL、詳細 |

説明欄は、決まった行を項目として読み取り、それ以外を詳細として表示する。

```text
会場: 下北沢某劇場
入り: 17:00
開場: 20:45
開演: 21:00
終演: 22:30
料金: 1,500円
チケット: https://example.com/ticket
グッズ販売あり
```

- 項目の行はなくてもよい。読み取れない場合は説明文としてそのまま表示する
- 項目名は `開演時間` のような表記と、全角空白の区切りも受け付ける
- `会場:` と `場所:` の行は場所として読む。カレンダーの場所が入っていればそちらを優先する。`会場: 1,500円` のような金額は料金として読む
- `入り` の行はサイトに表示しない。カレンダーは公開のため、入り時間自体は外部から読める
- 開場と開演の行がなければ、説明文の途中の `開場19:40` や `19時開演` のような記載を探す。複数あれば最初のものを使う
- 料金も、`料金:` の行がなければ説明文から探す。賞金などの誤読を避けるため、`🎫`、`料金`、`会場`、`配信`、`前売`、`当日`、`一般`、`学生` の直後の金額だけを読む
- 表の項目として読み取った部分は説明文から省く
- 120 文字を超える説明文は先頭だけを見せ、「続きを読む」で開き、「閉じる」で戻す
- 時間が見つからなければ「時間未定」と表示する。開始時刻を開演として表示しない
- 料金が見つからなければ、`src/data/prices.ts` に登録したライブ名の料金を使う（例：下北GRIP は無料）。ライブ名は全角と半角、大文字と小文字を区別せず、名前を含んでいれば一致とする
- 場所と料金が見つからなければ「未定」と表示する

未発表のライブは個人カレンダーと招待で管理し、共用カレンダーには入れない。
解禁日に共用カレンダーへ登録し、個人カレンダーの予定を削除する。
公開カレンダーの非公開予定は日時が外部から見える可能性があるため、非公開にして入れておく運用はしない。
登録ミスに備え、サイトでは `visibility` が `private` または `confidential` の予定を除外する。

中止になったライブは、共用カレンダーから予定を削除してサイトから外す。中止の案内は SNS で行う。
投稿済みの告知画像は自動では変わらない。

- API キーは Workers のシークレットに置き、Google Calendar API のみに制限する
- 説明欄は HTML を除去してから保持し、`set:html` は使わない
- 説明欄の URL は `http` と `https` のみリンクにする

### プロフィール（Markdown）

`src/content/` に置き、Astro の Content Collections で読む。

### お知らせ

サイトにお知らせ機能は持たず、告知は X で行う。

X の投稿をサイトに表示する機能も持たない。投稿の取得 API は少額でも従量課金で費用 0 円の
方針から外れ、無料のタイムライン埋め込みは読み込めないという報告があるため。

### 画像

外部ストレージは使わず `src/assets/` に置き、`astro:assets` でビルド時に WebP 変換と
リサイズを行う。サーバー描画の `/` では変換されないため、写真は幅 1200px の WebP にしてから
`src/assets/christopher.webp` に置く。元の写真はリポジトリに含めない。
画像がリポジトリを圧迫するほど増えたら Cloudflare R2（無料枠あり）へ移す。

## デザイン

縦積みのレイアウトとし、サイトカラーはベージュにする。
カードを敷き詰めるグリッドは使わない。
[サンドウィッチマンのプロフィールページ](https://grapecom.jp/talent_writer/sandwichman/) の
情報の並びを参考にするが、デザインや素材は流用しない。

| `surface` | `#FBF8F2` | プロフィール表などの背景 |

### 文字

- 書体は Noto Sans JP とし、サイト内に置いて配信する
- 見出しは日本語を大きく太字にし、上に `SCHEDULE` のような小さな英字を添える

### トップページの構成

上から順に並べる。スマートフォンを基準に作り、PC では余白と文字を広げる。

| 順 | セクション | 内容 |
| --- | --- | --- |
| 1 | ヘッダー | 名前、ページへのリンク |
| 2 | メインビジュアル | 写真に名前を白文字で重ね、下部に半透明の暗い層を敷く。PC は中央寄せ、スマートフォンは画面幅いっぱい |
| 3 | PROFILE（`#profile`） | コンビと各メンバーの項目の表 |
| 4 | SCHEDULE（`#schedule`） | 今後のライブすべて。過去のライブは折りたたむ |
| 5 | YOUTUBE（`#youtube`） | アップロード動画の再生リストの埋め込み（API キー不要で最新動画を表示） |
| 6 | LINKS（`#links`） | 各種リンク、問い合わせ先 |
| 7 | フッター | メールアドレスと告知画像の作成ページへのリンク、著作権表示 |

- ライブは「日付、ライブ名、会場」の行を区切り線で並べ、チケットがあればボタンを出す
- ヘッダーは画面上部に固定し、スクロール中も移動できるようにする

### 動き

リンクのホバーとセクションへのスクロールのみとし、`prefers-reduced-motion` のときは止める。
スライダーと読み込み画面は使わない。

## SEO と OGP

- ページごとに `title`、`description`、OGP を共通レイアウトで出力する
- `@astrojs/sitemap` で sitemap を生成し、`/schedule/poster` は除外する
- `public/` に `robots.txt` と既定の OGP 画像を置く

## 告知画像

月ごとのライブ日程を、SNS に投稿でき、TimeTree の予定スキャンでも読み込める画像として作成する。
更新担当者が `/schedule/poster?month=YYYY-MM` を開き、内容を確認して保存する。

### 生成方式

ブラウザの Canvas に描画して PNG にする。

- サーバーで生成しないのは、日本語フォントを含む処理が Workers 無料枠の CPU とサイズの制限に
  収まりにくいため
- HTML を画像に変換するライブラリを使わないのは、iPhone の Safari でフォントが欠けやすく、
  分割されたフォントの読み込みも重くなるため
- 保存は、対応端末では `navigator.share` で共有シートを開き、それ以外はダウンロードにする
- `noindex` を指定し、sitemap には含めない

### 画像の仕様

| 項目 | 内容 |
| --- | --- |
| サイズ | 1080 x 1350px（4:5） |
| 1 枚の件数 | 高さに収まる件数（最大 6 件）。超える場合は複数枚に分ける |
| 見出し | クリストファー、`YYYY年M月 ライブ日程`、複数枚なら `1/2` |
| 各行 | 日付と曜日、ライブ名、場所、開場 / 開演 / 終演、料金 |
| フッター | サイトの URL |

画面には予定の最終取得時刻を表示する。登録直後はキャッシュにより最長 10 分反映されない。
開場と開演の両方がない予定は「時間未定」とし、場所と料金がなければ「未定」とする。
長い名称は折り返す。

### TimeTree での読み取りやすさ

- 各行に `11/3（火）` のように月を含む日付を書く
- 文字は画像にせず同じ書体で、背景とのコントラストを高く保つ
- 項目名は `場所:`、`開場:`、`開演:`、`終演:`、`料金:` に統一する
- 予定スキャンは 1 枚で最大 10 件まで読み込める（2024 年の報道による）。1 枚 6 件なら収まる

実装時に実際の画像を TimeTree へ読み込み、日付、開始時刻、場所の精度を確認する。

## 品質と運用

- テスト対象は説明欄の読み取り、終日予定、月の境界、キャッシュの処理、不正な `month`、非公開予定の除外とする
- GitHub Actions で push 時に型チェック、lint、テストを実行する
- アクセス解析は Cloudflare Web Analytics を使う
- サイトの URL は `astro.config.mjs` の `site` に集約し、独自ドメインへの移行時はここを変更する。
  移行後は `workers.dev` から新しいドメインへリダイレクトする
